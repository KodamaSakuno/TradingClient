# ADR 0007：期权模块范围决策——本地美式定价模块而非交易所期权对接

- 状态：已接受
- 日期：2026-08-28

## 背景

项目需要展示期权领域的理解与实现能力，但面临两条截然不同的路径：接入 Gate/Binance 等加密交易所的期权接口，或在本地构建美式期货期权定价与分析模块。两条路径的标的资产、行权方式、结算规则和定价体系均不相同，不能简单混为一谈。

## 决策

**不接任何交易所期权接口**，改为构建本地期权分析模块：

- 数据来自 mock / 手工录入的标的行情。
- 定价体系以**国内商品期权**为基准：美式行权、标的为期货、行权后得到期货持仓。
- 引擎覆盖 Black-76 欧式基准、CRR 二叉树美式定价、BAW 近似、数值 Greeks、IV 反解、T 型报价与波动率微笑。

## 备选方案与理由

**接入 Gate/Binance 加密期权**：能展示真实市场数据。否决理由：

- 加密期权为欧式、标的为现货指数，行权以币本位或稳定币现金结算，与国内商品期权的"美式 + 期货标的 + 行权得期货持仓"体系差异过大。
- 接入加密期权会引入一套与本项目业务主线（期货做市、Delta 对冲、商品期权 Greeks 汇总）不一致的模型和符号体系。
- 本地模块已足以覆盖期权定价、Greeks、T 型报价、波动率微笑等核心能力，且更贴近目标业务场景。

**同时接入加密期权并在内部做两套模型**：覆盖更广。否决理由：双倍实现成本，且加密期权在本项目场景下的业务价值有限；先在一个体系内做到数值可信（解析解对照、模型间交叉验证），比两套都做半吊子更符合深度优先的范围原则。

## 后果

- `OptionSymbol` 四分量模型（标的/到期日/行权价/看涨看跌）仍作为前瞻设计保留，便于未来接入境内商品期权时复用。
- 本地模块的定价引擎、Greeks 计算、IV 反解全部沉淀在 Domain 层，零交易所依赖，便于单元测试和数值对照。
- 任何交易所期权适配的决策必须先回到本 ADR：若接入的是美式期货期权体系，可直接复用现有引擎；若接入的是欧式加密期权，则需重新评估是否值得引入第二套模型。

## 验证方式

- 定价与 Greeks 对照已知解析解的数值校验单元测试；IV 反解做往返一致性测试（Domain.Tests）。
- 美式与欧式的一致性交叉验证：CRR 二叉树在欧式场景下收敛到 Black-76。
- 范围约束由 AGENTS.md §13 规则 9 强制执行：仓库中不存在任何交易所期权适配器。
