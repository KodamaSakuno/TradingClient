# ADR 0006：市场环境拆分：行情主网 / 交易测试网

- 状态：已接受（实现中）
- 日期：2026-08-28

## 背景

在真实环境验证时，测试网（testnet / 模拟盘）通常流动性稀疏，盘口深度不足。若行情与交易必须绑定在同一环境，要么只能看到稀疏的订单簿，无法验证深度条、价格对齐与行情延迟指标；要么只能接入主网行情但不敢真实下单，无法验证签名、风控、订单推送等交易链路。

## 决策

将 `IMarketData` 与交易接口（`ISpotTrading` / `IFuturesTrading`）的环境选择解耦：行情可以接主网获取真实深度，交易可以接测试网完成真实下单闭环。组合方式通过配置决定，代码层面不感知具体环境的绑定关系。

Gate 现货的目标验证组合：行情走 Gate 主网，下单/撤单/余额走 Gate testnet。

## 备选方案与理由

**忍受稀疏盘口，行情与交易都接测试网**：最简单。否决理由：测试网挂单稀疏，订单簿深度条、价格精度对齐、行情延迟指标等 UI 能力无法得到有意义的验证；用户看到的界面与真实交易场景差距过大。

**行情与交易都接主网，但只看不下单**：能看到真实盘口。否决理由：无法验证交易全链路（签名鉴权、事前风控、订单推送、撤单、余额更新），而交易链路正是多交易所/账户模式抽象中最复杂的部分。

## 后果

- 接口垂直拆分使"行情主网 + 交易测试网"成为纯配置问题：同一个 `IMarketData` 实现可以指向主网，同一个 `ISpotTrading` 实现可以指向 testnet，组合在 Composition Root 完成。
- 新增环境（如模拟盘、UAT）只需新增适配器实例或配置项，不改上层代码。
- 该组合反过来证明 Application 层按产品线拆分接口不是过度设计：若行情与交易被绑在同一个巨型网关内，环境拆分将被迫在适配器内部写特殊分支，而非干净的配置组合。
- 混合环境下 UI 需显式标注行情与交易各自所属的环境；浮动盈亏等本地估算使用主网行情价格时，口径需在注释中写明（测试网成交价与主网行情存在价差）。

## 验证方式

- 落地后：Gate 主网行情 + testnet 交易的组合配置可运行，冒烟工具在混合环境下完成全链路（行情 → 下单 → 推送 → 撤单）。
