# ADR 0002：本地期权分析模块的定价引擎选型

- 状态：已接受
- 日期：2026-08-28

## 背景

本地期权分析模块不接入任何交易所期权接口，仅通过 mock 数据展示期权定价与分析能力：定价、Greeks、IV 反解、T 型报价、波动率微笑、持仓 Greeks 汇总。国内商品期权（大商所/郑商所）为**美式行权、标的为期货**，与加密期权的欧式、标的为现货/永续差异很大，因此定价体系必须以美式期货期权为基准，而不是直接套 Black-Scholes/Black-76 欧式公式。

## 决策

定价引擎全部放 `Domain/Options/`，纯函数、零第三方依赖，便于数值对照测试：

- **Black-76**：欧式期货期权基准（解析解 + 解析 Greeks）。地位是"欧式下界"，不用于美式报价。
- **CRR 二叉树**：美式期货期权定价基准实现，逐节点处理提前行权，收敛到真实美式价；欧式模式（`american=false`）用于"树收敛到 Black-76"的一致性测试。
- **BAW（Barone-Adesi-Whaley 1987）**：美式二次近似，供 IV 反解与 T 型报价批量定价等高频调用；与二叉树的差值即近似误差展示点。
- **Greeks**：Black-76 用解析解；美式用 bump-and-revalue 中心差分数值 Greeks（对任意定价委托统一适用）。
- **IV 反解**：Newton 迭代 + 二分兜底；基于美式价格反解。

## 备选方案与理由

**只用 Black-76 定价**：实现最省。否决理由：美式期权有提前行权溢价，欧式公式会系统性低估；保留美式与欧式模型并存，可直观对比提前行权溢价。

**用 Longstaff-Schwartz（LSM）蒙特卡洛**：能处理复杂行权特征。否决理由：本地 mock 场景无路径依赖，LSM 收敛慢、实现复杂度远高于 CRR；CRR 对单因子美式已足够精确，且能给出确定性的收敛行为供一致性测试。

**Greeks 全用解析解**：Black-76 已有解析式。否决理由：美式无解析 Greeks，逐模型手写解析式易错且无法复用；bump-and-revalue 对任意定价委托统一，代价只是常数倍定价调用，本地批量规模可接受。

## 后果

- 美式价精度依赖二叉树步数与 BAW 近似误差，由数值对照测试兜底（`BinomialTreeTests`、`BawApproximationTests`、`Black76Tests`、`AmericanGreeksTests`、`ImpliedVolatilityTests`）。
- 日期换算固定 ACT/365、Greeks 步长与单位（Vega 按 1 个波动率百分点、Theta 按自然日、Rho 按 1 个利率百分点）在代码注释中钉死，后续做波动率曲面拟合时沿用。
- 模块不接任何交易所期权接口；若未来接入，四分量 `OptionSymbol` 已预留，定价引擎与交易所符号格式化解耦。
